# AI 使用记录

## 工具与分工

| 环节       | Codex 的作用                                                    | 人提供或确认的内容                                  |
| ---------- | --------------------------------------------------------------- | --------------------------------------------------- |
| 要求拆解   | 将六项题目映射到 Demo、说明 PDF、备用视频和记录                 | 提供原始题目、指定 shadow6 仓库                     |
| 产品方案   | 提出独立咖啡店主、事实确认、素材绑定脚本和局部改写              | 候选人已确认咖啡店主场景，重点做事实确认与局部改写        |
| 个人经历   | 根据简历整理立行的可观察执行、局部恢复与产品改进判断            | 用户表示第一个 Multi-Agent 项目最满意，提供本人简历 |
| 实现       | 编写 HTML/CSS/JavaScript、原创 SVG 示例、浏览器测试和录屏脚本   | 不宣称候选人逐行手写或单独完成视觉设计              |
| 验证和交付 | 实际启动浏览器、检查导出和恢复、生成截图/PDF/视频、部署静态网页 | 候选人最终检查并决定提交                            |

没有使用真实 AI 生成 API，也没有让上传素材离开浏览器。生成是确定性本地规则；因此本次只验证流程和控制感，不声称验证真实模型的生成质量。

## 没有直接接受的 AI 初稿

1. “一键产出视频”超出实际实现：改成“拍摄小笺”，分镜预览明确注明无音轨、不是成片。
2. 图片读取可能迟到覆盖：增加每个素材位的版本检查，替换、移除和回首页时使旧结果失效。
3. 三张图可以选择重复用途，造成镜头绑定不清：补上成品、制作、环境三种用途不能重复的检查。
4. 草稿易被理解为会保存原图：只持久化文字与示例标记，不存本地图片；界面说明自己的图片刷新后需重新选择。
5. 初稿没有清楚区分事实与表达：增加前置确认，不补全缺失价格；浏览器断言验证空价格结果不包含价格。
6. 第 5 题不能凭空生成一次旅行：改为用户已有项目的开发与回归测试经历，不添加未提供的目的地、同行者或真实用户反馈。

## 判断的来源与限制

“立行”的经历来自本人简历和明确偏好。本题目标用户与核心流程由 AI 提案；候选人已明确认可独立咖啡店主场景，选择重点做好事实确认与局部改写，不做一键成片。未进行真实商家访谈，不把确认提案等同于已验证需求。测试数字仅指当前原型的可重复自动检查，不代表用户满意度、市场规模或真实经营收益。

代码、说明文字、示例插画和演示视频均为本次作业新建；依赖 Playwright、ReportLab、pypdfium2 按各自许可证使用。未复用外部产品源码或付费素材。个人简历不入库。
